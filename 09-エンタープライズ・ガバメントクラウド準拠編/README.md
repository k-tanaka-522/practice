# 09-エンタープライズ・ガバメントクラウド準拠編

## 🎯 このモジュールで学ぶこと

**実務で求められるエンタープライズ級のAWS構成とガバメントクラウド準拠設計**を、2つの実践的なケーススタディを通じて体系的に習得します。

### 学習目標

1. **マルチアカウント戦略の理解**: なぜ単一アカウントでは不十分なのか
2. **共通系アカウント設計**: セキュリティ、監視、ネットワークの集約管理
3. **Transit Gateway によるネットワーク統合**: 複数VPCとオンプレミスの接続
4. **ISMAP・ガバメントクラウド準拠**: 政府・自治体システムで求められるセキュリティ要件
5. **実践的なシステム構築**: 役所設備管理システムと水産養殖統合管理システムの実装

## 📚 なぜこのモジュールが必要か

### 01-08編との違い

```yaml
01-08編（基礎学習）:
  対象: AWS初心者
  構成: 単一アカウント
  目的: 基本サービスの理解と操作習得
  環境: 学習・検証用

09編（実務レベル）:
  対象: 実務でAWSを使う人
  構成: マルチアカウント
  目的: エンタープライズ級システムの構築
  環境: 本番・準本番を想定
```

### 実務でマルチアカウントが必要な理由

```
単一アカウントの限界:
  ❌ セキュリティ境界が曖昧
  ❌ 開発・本番環境の分離が不十分
  ❌ コスト配分が困難
  ❌ 権限管理が複雑化
  ❌ 障害の影響範囲が広い

マルチアカウントの利点:
  ✅ アプリケーションごとにアカウント分離
  ✅ セキュリティ・監視・ネットワークを共通系で集約
  ✅ 明確なコスト配分
  ✅ きめ細かい権限管理
  ✅ 障害の影響を最小化
```

## 💰 コスト管理

### 予想コスト（月額）

```yaml
学習環境（最小構成）:
  - Organizations: 無料
  - Transit Gateway: $36/月（1アタッチメント）
  - VPC: 無料
  - EC2/ECS (t3.micro): $20-40/月
  - RDS/DocumentDB (t3.medium): $60-100/月
  - その他（ログ、監視等）: $20-40/月
  - 合計: $136-216/月

本番相当環境:
  - マルチアカウント構成: $200-400/月
  - Transit Gateway (複数): $100-200/月
  - Direct Connect (オプション): $300-500/月
  - ECS Fargate 本番: $200-400/月
  - DocumentDB 本番: $300-500/月
  - セキュリティ・監視強化: $100-200/月
  - 合計: $1,200-2,200/月
```

### コスト最適化のポイント

- 🔍 **学習用は最小構成**: t3.micro, db.t3.medium を活用
- ⏰ **使わない時は停止**: 開発環境は夜間・週末停止
- 🧹 **不要リソースの削除**: 学習完了後は即座に削除
- 💡 **無料利用枠活用**: CloudWatch Logs、CloudTrail 等

## 🛡️ セキュリティとコンプライアンス

### ISMAP準拠のポイント

```yaml
機密性レベル3の要件:
  ✅ 監査ログの確実な記録と保護
  ✅ 通信の暗号化（TLS 1.2以上）
  ✅ データの暗号化（保存時・転送時）
  ✅ アクセス制御の厳格化
  ✅ 脆弱性管理とパッチ適用
  ✅ インシデント対応体制
```

### 実装済みセキュリティ機能

- 🔐 **IAM ベストプラクティス**: 最小権限、MFA必須
- 🛡️ **ネットワークセキュリティ**: プライベートサブネット、セキュリティグループ
- 🔒 **暗号化**: KMS による暗号化（保存時・転送時）
- 👤 **監査ログ**: CloudTrail 全リージョン有効化
- 📊 **セキュリティ監視**: Security Hub、GuardDuty 統合

## 🚀 クイックスタート

### 前提条件

```bash
# AWS CLI確認
aws --version
aws sts get-caller-identity

# 複数のAWSアカウントへのアクセス権限
# - Management Account (Organizations管理用)
# - Shared Account (共通系)
# - Service Account(s) (アプリケーション用)

# または、Organizations管理権限があるアカウント
```

### セットアップ手順

```bash
# 1. リポジトリ移動
cd 09-エンタープライズ・ガバメントクラウド準拠編

# 2. パラメータ設定
cp parameters.sample.json parameters.json
# parameters.json を編集してアカウントIDなどを設定

# 3. Organizations セットアップ（9.1）
```
